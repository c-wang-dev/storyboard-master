# 分镜大师架构说明

## 总览

分镜大师是一个**决策端 Agent**：输入剧本片段，输出可执行的分镜与提示词包，供下游生图/生视频工具执行。核心设计原则：**决策可解释、质量可评估、知识可沉淀**。

```
剧本片段
   │
   ▼
┌───────────────────────────────┐
│ ① 模型分流（死锁模型卡）        │  ← 先选生图/生视频模型，锁定参数表
└───────────────────────────────┘
   │
   ▼
┌───────────────────────────────┐
│ ② 决策引擎（六维 → 五表 → 仲裁）│  ← 内容类型/信息焦点/情绪/权力/空间/节奏
└───────────────────────────────┘   → 景别/角度/运镜/光影/节奏 + 时长档位
   │
   ▼
┌───────────────────────────────┐
│ ③ 知识检索（三层降级）          │  ← 语义检索 → MOC 导航 → 关键词兜底
└───────────────────────────────┘
   │
   ▼
┌───────────────────────────────┐
│ ④ 表演一致性（四层机制）        │  ← 性格范式 → 锚定卡 → 禁止清单 → 远景降级
└───────────────────────────────┘
   │
   ▼
┌───────────────────────────────┐
│ ⑤ 提示词包输出 + 12 项质量自检  │  ← 镜头运动/构图关键词显式化，负面词合并
└───────────────────────────────┘
   │
   ▼
       下游模型工具（生图/生视频 API）
```

## 四层表演一致性

| 层 | 机制 | 解决 |
|---|---|---|
| L1 | 性格范式库（8 范式） | 角色"是谁"——行为基调 |
| L2 | 角色锚定卡（项目级绑定） | 一次绑定全剧生效 |
| L3 | 禁止表演清单（闸门） | 阻止范式外动作/情绪漂移 |
| L4 | 远景体态降级 | 神态不可见时用体态维持辨识度 |

## 知识库组织（五层）

```
决策层   分镜决策引擎.md（决策表/仲裁/负面清单）
知识层   镜头语言 / 电影语法 / 光影色彩 / 风格参考 / 转场衔接 / 音频配方
参数层   参数速查表（6 模型卡）/ 权重控制 / 多帧一致性 / 场景配方
归档层   视频学习记录（影视案例五维分析）
度量层   评测基准集 / 成本台账 / 治理规则
```

## 三道闸门（知识写回护栏）

1. **写入三查**：查重 → 冲突仲裁 → 三要素（来源/日期/置信度）
2. **人工确认**：检索未命中生成的内容标记"待验证"不落库；用户明确满意才写回
3. **周期治理**：每投喂 10 部视频全库体检；容量红线（实例区软 20/硬 30 条）

## 模型分流（Tool Use 路由）

用户选定模型 → 死锁到对应模型卡 → 其他模型不检索。防止 SD 系参数（CFG/Steps/tag 语法）混入自然语言系模型（即梦/Seedream/可灵等）。

## 证据分层

- ✅ 机器实测：镜头数/时长/边界（ffmpeg 量化）
- 🧪 视觉推断：景别/运镜/表演细节（需人工校准）
- 📖 公开资料：剧情/资料引用

推断内容绝不伪装成实测结论，保证知识库可信度。

## 与执行端的关系

本仓库为**决策端**。执行端（真实调用生图/生视频 API、批量调度、质检回传）为独立工程，可通过提示词包 JSON 与 REST/MCP 接口对接，保持决策与执行解耦。
