# 知识库治理规则（防紊乱宪章）

> **用途**：视频学习影片增多后，防止知识库出现膨胀、重复、矛盾、置信度混杂五类紊乱。所有「向主库回填内容」的操作（视频投喂回填 / 自我成长写回 / 笔记归档）**必须遵守本规则**。
> **一句话原则**：数据只能逐层「提炼」上行，不能倾倒。原始层永远全量，精炼层有准入有红线，稳定层只在人工拍板后变。
> 制定日期：2026-08-23

---

## 一、三层存储模型

| 层 | 成员 | 增长规则 | 是否进主检索 |
|----|------|---------|:---:|
| **① 原始层** | `视频学习记录/`（每片一档） | **只增不删**，全量留档，永远可追溯 | 否（经 README 亮点索引表按需读取） |
| **② 精炼层** | 实例归档区×3（[[镜头语言]]§七 / [[光影与色彩]]§六 / [[风格参考库]]§六）+ [[转场与片段衔接库]]§四 + [[音频指令配方库]]§三 + [[打斗动作库]] / [[特效库]] / [[明星演技样本库]] | **有准入**（过闸门 A）**有红线**（见第三节） | 是 |
| **③ 稳定层** | [[分镜决策引擎]]五表 / [[参数速查表]]模型卡 / [[分镜知识库MOC]] | **只在人工拍板后变更**（过闸门 B），条目数基本恒定——只换血，不增肥 | 是（最高优先） |

## 二、三道闸门

### 闸门 A · 写入三查（每次回填/写回/归档必过）

1. **不重复（查重合并）**：回填前先查目标库是否已有同技法条目。已有 → **合并出处，不新增条目**（如"逆光剪影"已有灵笼实例，哪吒再教同技法就追加出处行，不开新条）。
2. **不矛盾（冲突仲裁）**：新内容与现有条目冲突时按仲裁规则处理（见第四节）。
3. **不冗余（三要素强制）**：每条新实例必带「**片名 / 日期 / 置信度**」三要素（📖官方 > ✅实测 > 🧪视觉推断），无出处的条目不准入。

### 闸门 B · 确认拍板（精炼层 → 稳定层）

- 决策表 / 模型卡 / MOC 结构的任何修改，**必须人工确认后执行**（现有铁律的延伸）。
- 实例区数据要"升级"成决策规则（如实例节奏数据改写节奏决策表）时，同样过本闸门。

### 闸门 C · 周期治理（每投喂 10 部影片触发一次）

1. **全库体检**：重复扫描（同技法多出处条目）+ 矛盾扫描（新旧数据冲突）+ ovault 断链检查 + deprecated 清点 + 容量清点（更新第五节登记表）。
2. **输出治理报告**：列出建议合并项 / 建议淘汰项 / 矛盾仲裁建议，交人工拍板。
3. **淘汰执行**：拍板后才删。**无确认不删，铁律不变**；淘汰条目可转存回原始层对应记录文件后从精炼层移除。

## 三、容量红线（2026-08-23 拍板）

| 对象 | 软限 | 硬限 | 触线动作 |
|------|:---:|:---:|---------|
| 单个实例归档区 | 20 条 | 30 条 | 软限：提示收紧准入；硬限：**必须处理**——①拆独立实例文件（如 `实例归档_镜头语言.md`，MOC 登记，主库留指针）或 ②按淘汰顺序清退 |
| 主库文件行数 | 500 行 | 600 行 | 触硬限即拆分或精炼，超限文件不得再追加 |

**淘汰顺序**（从先到后）：🧪最低置信度条目 → 长期未被检索引用的条目 → 已标 deprecated 的条目。✅实测且被高频引用的条目不淘汰。

## 四、冲突仲裁规则

| 情形 | 裁决 |
|------|------|
| 新旧条目矛盾，置信度不同 | **置信度高者胜**（✅实测 > 🧪视觉推断） |
| 置信度相同 | **新者胜**（数据新鲜度优先），旧条目标 `deprecated` 保留不删 |
| 涉及决策表 / 模型卡级矛盾 | **必须人工拍板**，AI 不得自行裁决 |
| 模型参数过时（模型版本更新） | 标 `deprecated` 不删（保鲜纪律：过时标 deprecated，永不物理删除） |

## 六、与其他机制的关系（防规定打架）

- 本规则**不取代**既有纪律，只做统辖：自我成长写回的三查闸门 = 本规则闸门 A；「无人工确认绝不写回」= 闸门 B；模型参数保鲜（deprecated 不删）= 第四节仲裁规则；备份 + ovault check 照旧。
- [[视频学习五维框架]] 与 [[视频学习记录/README]] 的归档去向规定，均以本规则为上位约定：**去向不变，但回填前必过闸门 A，容量与淘汰按本规则执行**。
