# 分镜知识库 — Obsidian Vault 联动检索

当「分镜大师」专家需要生成人物三视图提示词、场景氛围图提示词或分镜图提示词时，必须先检索 Obsidian vault 中的专业知识，确保提示词术语准确、技法描述专业。

## Vault 信息

- **路径**：`<你的Obsidian库路径>`
- **专业知识目录**：`分镜知识库/`
- **操作原则**：读取为主。仅在「笔记归档」流程中对知识库文件执行追加写入（append），绝不修改已有内容、不删除已有文件、不移动文件。

## 检索策略

### 步骤 0：模型分流（先选后锁，最高优先级）

**任何生成提示词/参数建议之前，必须先确认使用者选定的模型**，再死锁到对应模型卡：

- **生图模型**（三选一）：即梦 image2 / Seedream 5.0 Pro / Flux
- **生视频模型**（三选一）：Seedance 2.5 / 可灵 3.0 / 通义万相 2.7

**死锁规则（硬）**：
1. 选定后，全程只按选定模型的模型卡输出，**其他模型的字段/参数不出现、不检索**。
2. 参数从 `参数速查表.md` 取对应模型卡，**不得混用其他模型卡的参数**（这是历史教训：SD 的 CFG 混进即梦提示词）。
3. 一致性机制按 `多帧一致性策略库.md` 的对应模型档位（参考图/首帧/元素参考/LoRA）。

### 步骤 1：确定检索目标

根据当前任务模块确定需要检索的知识领域：

- **人物三视图** → 检索 `性格范式库.md`（判定性格范式 + 建立角色锚定卡）+ `角色微表情库.md`（微表情配置）+ `光影与色彩.md`（光照描述）+ `提示词工程.md`（角色提示词模板）+ `风格参考库.md`（角色设计风格）
- **场景氛围图** → 检索 `镜头语言.md`（景别/构图）+ `光影与色彩.md`（色调/氛围）+ `提示词工程.md`（场景提示词模板）
- **分镜图** → **先读 `分镜决策引擎.md`（决策先行：选档 5s/10s/15s + 五表定景别/角度/运镜/光影/节奏 + 交叉表定图数）**，再按 `提示词模板.md` 模板 C 填空；检索 `镜头语言.md`（运镜/景别/构图 + §七实例归档区）+ `电影语言的语法核心规则.md`（轴线/机位/剪辑）+ `性格范式库.md`（角色锚定卡/禁止表演）+ `角色微表情库.md`（情绪微表情）+ `光影与色彩.md`（+ §六实例归档区）+ `提示词工程.md`（连续镜头提示词）+ `视频学习记录/`（参考案例）+ `多帧一致性策略库.md`（跨帧一致性）+ `转场与片段衔接库.md`（步骤 0 片段衔接检查）；**打戏镜头** 追加 `打斗动作库.md`；**特效镜头** 追加 `特效库.md`；**角色已绑定演技样本** 时先执行下方「角色复刻绑定工作流」
- **视频学习** → 检索 `视频学习五维框架.md`（分析框架）+ `性格范式库.md`（判定性格范式）+ `角色微表情库.md`（微表情定位）；**技法回填主库前必过 `知识库治理规则.md` 闸门 A（查重合并/冲突仲裁/三要素），实例区参考案例先查 `视频学习记录/README.md` 亮点索引表再按需读档**
- **生成参数 / 提示词包附带参数建议** → **先执行步骤 0 模型分流（死锁模型卡）** → `参数速查表.md`（取对应模型卡）→ `多帧一致性策略库.md`（锁角色）→ `场景配方库.md`（套场景配方）；**视频提示词** 追加 `转场与片段衔接库.md`（衔接选型）+ `音频指令配方库.md`（音频行配方）；负面词合并 `分镜决策引擎.md` §六 全局负面清单 A 层

### 步骤 2：执行检索（三层策略，自动降级）

检索按以下优先级执行。**每层失败立即降级到下一层，不报错、不阻塞、不询问用户**：

#### 第 1 层：语义检索（语义相近 > 关词匹配，优先用）

**前置条件探测**（两个都满足才用）：
1. vault 的 `.smart-env/multi/` 目录下存在 `分镜知识库` 相关的 `.ajson` 索引文件
2. smart-cli 可用（node 与 `@yejianye/smart-connections-mcp` 已安装，见文末"环境依赖"）

执行方式：

```
NODE_PATH="<你的 node 模块安装路径>" "<你的 node.exe 路径>" "<你的 node_modules>\@yejianye\smart-connections-mcp\bin\smart-cli.js" lookup "{自然语言查询}" --vault="<你的 Obsidian vault 路径>" --limit=8
```

- 查询用**自然语言描述意图**（如"反派角色压抑愤怒时的微表情序列"），不要堆关键词
- 命中的笔记路径 + 相似度分数用于缩小 Read 范围

#### 第 2 层：MOC 导航（结构化入口，零依赖）

Read `分镜知识库/分镜知识库MOC.md`（知识库总入口），根据 MOC 中的模块说明和双链直接定位目标文件——适合明确知道知识领域的场景（配合步骤 1 的检索目标表）。

#### 第 3 层：Grep 关键词（兜底，永远可用）

```
Grep pattern="关键词1|关键词2|关键词3" path="<你的知识库路径>" output_mode="content" -n -C 2
```

关键词示例：
- 景别搜索：`远景|全景|中景|近景|特写|extreme|close-up|wide shot`
- 运镜搜索：`推|拉|摇|移|跟|升|降|dolly|pan|tilt|track`
- 光影搜索：`逆光|侧光|顶光|柔光|硬光|Rembrandt|butterfly|rim light`
- 色调搜索：`暖色调|冷色调|高调|低调|saturation|palette|mood`
- 风格搜索：`赛博朋克|水墨|写实|anime|oil painting|concept art`
- 表演搜索：`阴狠|隐忍|暴戾|阳奉阴违|微表情|禁止表演|锚定卡`

**降级判定**：语义检索无结果/超时/工具不可用 → MOC 导航；MOC 文件不存在 → Grep。任何一层拿到足够结果即可停止，不必三层全跑。

## 角色复刻绑定工作流（打斗/特效/演技样本的场景化调用入口）

### 触发时机

- 使用者说「用角色N 演剧本里的XX」/「XX 按角色N 的演法」等绑定指令
- 解析任何剧本镜头前（检查是否有已生效的项目绑定）

### 工作流

1. **解析剧本前**：Glob 查找 `分镜知识库/项目绑定/*_角色绑定表.md`。存在 → Read 绑定表，凡绑定记录中的角色，其镜头表演设计自动应用对应样本基底（读 `明星演技样本库.md` 对应样本卡）
2. **收到绑定指令**：
   - 校验唯一性（该样本是否已被本剧其他角色占用，占用则报告并要求二选一）
   - 按 `项目角色绑定表_模板.md` 建立该项目绑定表（复制到 `分镜知识库/项目绑定/{项目名}_角色绑定表.md`），写入绑定记录
   - 之后全剧有效，使用者不必每集重复说明
3. **冲突处理**：剧本性格与样本习惯冲突时，**剧本性格 > 样本习惯**（样本只决定"怎么演"，剧本决定"演什么人"），冲突明显时向使用者提示
4. **输出闸门（硬规则）**：提示词包中只出现中性表演描述（如"威压式凝视、开口前停顿半秒、脊背挺直"），**绝不出现**样本编号、真名、"像某演员"类表述——这是法律红线（肖像权/人格权）+ 下游平台名人名拦截的双重要求
5. **降级规则**：标志习惯只在关键镜头（特写、情绪转折）使用；远景等神态不可见的景别，降级为体态/动作特征

### 复刻边界

✅ 复刻：演技、神态、动作、节奏、气场（行为模式，可抽象可输出）
❌ 不复刻：声音、长相、真名（人格权载体，不进样本卡不进输出）

## 自我成长工作流（检索未命中时的生成-验证-写回闭环）

> 目标：让知识库在使用中自我进化。本流程是「知识缺失处理」的升级版——从"缺失就告知"升级为"缺失就生成候选，经护栏闭环写回"。
> 核心铁律：**生成 ≠ 写入**。自由发挥的内容必须经两道护栏（待验证标注 + 三查闸门）才能落库。

### 触发时机

三层检索（语义 → MOC → Grep）全部未命中，且使用者需要的内容知识库确实没有。

### 流程

1. **自由发挥生成候选**：用通用专业知识生成使用者需要的内容（提示词 / 技法 / 参数建议等），输出末尾标注「🧪待验证」。
2. **候选不落库**：待验证内容只用于本次输出，**不写入知识库，也不作为下次生成的检索依据**（切断自指循环）。
3. **等待使用者反馈**：使用者反馈「满意 / 正确 / 就这版」→ 触发写回；反馈「不对 / 修正」→ 按修正重生成，仍标待验证。
4. **三查闸门**（写回前必过）：
   - **不矛盾**：对照目标模块现有条目查冲突（冲突则合并/修正，不直接追加）
   - **不重复**：查知识库是否已有同类内容（重复则丢弃或只补增量）
   - **不冗余**：删掉无效、机器不会调用的内容
5. **写回 + 升级置信度**：三查通过 → 归档到对应模块（按归档判定表，并遵守 `知识库治理规则.md` 的容量红线与冲突仲裁）→ 备份 + ovault check → 内容置信度从「🧪待验证」升级为「✅实测」。

### 硬规则

- ❗ 无使用者明确的「满意」反馈，**绝不写回**（禁止无人确认的自动写回）
- ❗ 待验证内容**绝不**参与下次生成的检索依据
- ❗ 三查有一项不过就打回，不勉强写回
- ❗ 写回照旧走备份 + ovault check（零断链）

## 笔记归档流程（写入能力）

当用户对你说「帮我归档这条笔记」「整理一下这个笔记」「把这个归到知识库」等类似指令时，进入归档流程。

### 归档触发词

`归档` / `整理笔记` / `归类` / `放到知识库` / `存到对应模块`

### 归档流程

#### 1. 定位笔记文件

用户可能：
- 直接说了一个文件名（如「归档 逆光技巧.md」）
- 在 vault 里新建了一个文件让你去找
- 直接贴了一段文字内容让你归档

**找文件**：如果用户只给了文件名，用 Glob 在 vault 里搜索：

```
Glob pattern="**/*{文件名关键词}*" path="<你的Obsidian库路径>"
```

**贴文字**：如果用户直接贴了内容，先将其写入一个临时文件 `分镜知识库/_待归档_临时.md`，然后按正常流程处理。

#### 2. 读取并分析笔记内容

使用 Read 读取笔记全文，分析其核心主题。

#### 3. 分类判定

根据笔记内容的核心主题，判定归入哪个模块：

| 模块文件 | 判定关键词 | 内容范围 |

- 笔记内容同时涉及多个模块时，选择**最核心的主题**归入一个模块，不要重复归档
- 如果无法明确判定，向用户展示候选模块并让用户选择
- 如果内容完全不属于任何模块（如纯个人日记），如实告知用户并建议手动放置

#### 4. 追加写入目标文件

判定目标模块后，读取目标文件的当前内容，在文件**末尾**追加新章节：

```markdown
## {笔记标题或主题概括}

> 归档时间：{YYYY-MM-DD} · 来源：用户笔记

{笔记正文内容，保持原始格式}
```

**写入规则**：
- 只追加，不修改已有内容
- 追加位置：文件最末尾
- 保留笔记原文的 Markdown 格式
- 如果笔记没有标题，根据内容自动生成一个简洁的标题

#### 5. 清理临时文件

如果归档的是 `分镜知识库/` 下的独立文件（非 `_待归档_临时.md`），归档完成后**询问用户**是否删除原文件：

> 笔记已归档到 `光影与色彩.md`。是否删除原始文件 `逆光技巧.md`？

用户确认后才删除。`_待归档_临时.md` 归档后直接删除，不询问。

#### 6. 归档报告

归档完成后，输出报告：

```
✅ 归档完成

归档位置：分镜知识库/{目标文件}.md
新增章节：## {章节标题}
原始文件：{已删除 / 已保留}
内容摘要：{一句话概括笔记内容}
```

### 归档安全规则

- ❗ 绝不修改目标文件中已有的任何内容，只在末尾追加
- ❗ 绝不删除用户主动创建的笔记文件，除非用户确认
- ❗ 绝不移动、重命名 vault 中的已有文件
- ❗ 如果目标文件读取失败，停止归档并报告错误，不猜测文件内容

---

## 注意事项

- vault 路径使用正斜杠 `/`
- 搜索时大小写不敏感，使用 `-i` 参数
- 优先搜索专业目录再搜全库，避免无关结果
- 每条提示词生成前都应至少检索一次相关知识点
- 不要因为 vault 中没有完美匹配就跳过检索——模糊搜索可能找到意外有用的内容
